Prove what a policy change does before it ships.

A tidy-up PR regroups a few rules and quietly lets someone delete production. Reviewers read the diff and see nothing wrong, because the diff of the file is not the diff of the decisions. Proofgate computes the second one, exactly.

Try it in your browser View source

One idea, three languages

Each language does the part it is best at. The prover that runs in the demo below is the same Rust code the gateway shells out to, compiled to WebAssembly.

Ruby

Write the policy

A small DSL. Rules, and the invariants that must never break, read like the sentence they mean. Mistakes point at the line.

Rust

Prove the change

Treats the request space as hyper-rectangles and computes the exact set of requests whose decision flips, and whether each invariant holds for all of them.

Go

Gate the deploy

Serves decisions and refuses a bundle that breaks an invariant, or that widens access without an approval bound to that exact diff.

What the gateway enforces

The candidate must prove every invariant.If any never or always fails, the bundle is rejected and the old one keeps serving.
Widening needs an approval for that exact change.An HMAC over the old digest, the new digest and the fingerprint of every flipped request. Edit the policy afterwards and the token stops verifying.
Every decision is on a hash chain.Activations and rejections are appended to a log where each entry commits to the one before it. Edit or remove a line and verification fails.
